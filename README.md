## What is implemented in this source

- Electron + React + TypeScript desktop shell, secure preload/IPC boundary, title bar, sidebar, footer and app identity.
- Arabic/English interface, RTL/LTR, Manrope/Cairo typography, System/Light/Dark theme, compact/expanded cards.
- Persistent preferences and download history using `electron-store` (JSON on disk; not SQLite).
- URL metadata extraction and queue/download processes through a bundled Windows `yt-dlp.exe` runtime.
- Video/audio formats, quality caps, subtitle options, time-range trim, output folder and per-task settings.
- Playlist expansion into independent video tasks (up to 500 entries per playlist preview).
- Pause/resume/cancel/retry, file open/folder open/rename, progress and final file-size reporting.
- In-app and Windows notifications, replaceable WAV sounds, sound volume and per-event preferences.
- GitHub Release update checks, SHA-256 verification, NSIS installer update and portable executable replacement.
- Windows x64 NSIS Installer and Portable build workflows, CI and basic tool smoke checks.

## Limitations and honest support statement

- A website may change its player or access rules at any time. The app can only download public/accessible media that the bundled `yt-dlp` version can extract.
- Availability of quality levels, audio formats, subtitles, duration metadata and file-size estimates depends on the source.
- Private/login-only media, DRM, paywalls and access-control bypass are not supported. No browser cookies or account credentials are imported.
- Playlist previews are capped at 500 entries to avoid unbounded memory and UI load. A longer playlist is not fully enumerated by the current version.
- Format conversion and trimming depend on the bundled FFmpeg build. The output file is verified after the downloader exits, but a failed/canceled download can leave a partial file.
- The app has not been exercised against every source site or on a clean Windows computer from this environment. The first public release should be treated as a beta until the release workflow and installer are verified on Windows.
- Windows builds are currently unsigned. SmartScreen may show a warning until the publisher signs the application and builds reputation.

## Development on Windows

Requirements: Windows 10/11 x64, Git for Windows, Node.js `22.22.2` or newer in the Node 22 line, and npm.

```powershell
npm ci
npm run prepare:tools:win
npm run verify:tools:win
npm run dev
```

Run quality checks and create both Windows packages:

```powershell
npm run check
npm run build
npx electron-builder --win nsis portable --x64 --publish never
```

The installers are written to `release/`. `resources/tools/win32-x64/` is generated by `prepare:tools:win` and is intentionally not committed to Git because it contains third-party binaries. The build script downloads official upstream assets, verifies the yt-dlp SHA-256 file and records tool versions/licenses.

## Build and publish with GitHub Actions

1. Push the project source to `main` in the official repository.
2. Confirm `package.json` version and the tag match (currently `1.0.0` / `v1.0.0`).
3. Push a tag that matches the package version (for example, `v1.0.0` for version `1.0.0`).
4. The `Build and publish Windows release` workflow runs on `windows-latest`, runs checks, fetches yt-dlp/FFmpeg/Node, verifies tool binaries, builds both EXEs, creates checksums and publishes a GitHub Release.
5. Review the Actions log and download the workflow artifacts before announcing the release.

A PowerShell helper `PUBLISH-TO-GITHUB.ps1` is included for the repository owner. On Windows, extract the source, open PowerShell in the project folder, run `Set-ExecutionPolicy -Scope Process Bypass` and then `./PUBLISH-TO-GITHUB.ps1`. Review the staged changes and type `PUBLISH` only after reviewing the files and the MIT license. The helper pushes the current working tree to the configured official repository and may publish the version tag configured in the script. Check the script's tag value before running it. Git for Windows and an authenticated GitHub session are required. If Git does not have an author identity yet, configure `git config --global user.name` and `git config --global user.email` with your own details first.

## Design rules

No emoji, no platform logos or platform imagery, Lucide icons only, solid backgrounds only, no decorative gradients or wallpaper images. Video thumbnails are shown only when returned by the supplied media URL. The splash screen uses the centered BVD mark, a subtle shadow and restrained motion with reduced-motion support.
